# Equinibrium Magic Box Runtime

The runtime is the deployable host/container layer around the invariant-driven execution boundary.

## Contract

```text
Autonomous controller
        |
        | opaque execution payload
        v
   HTTP /execute
        |
        v
+-----------------------+
| Equinibrium Magic Box |
| GIE                   |
| Safety                |
| Identity              |
| Freshness             |
| Commit Gate           |
+-----------+-----------+
            |
            | only after ALLOW
            v
      Actuator Adapter
            |
            v
       Host I/O
            |
            v
      Physical device
```

The CPU, Linux distribution, container runtime and physical I/O technology are deployment details. The governance core has no Raspberry Pi dependency.

## API

`GET /health` — liveness.

`GET /state` — current authority epoch and relay state.

`POST /authorize`

```json
{"env_id": 0}
```

Returns the newly issued authority epoch.

`POST /revoke`

```json
{"env_id": 0}
```

Revokes the current authority. Previously stamped execution objects remain stale and are blocked.

`POST /execute`

```json
{
  "env_id": 0,
  "execution_epoch": 1,
  "payload_b64": "UkVMQVk6T04=",
  "safety": "ALLOW"
}
```

The runtime hashes the exact payload and sends it through the existing GIE → Safety → Commit Gate composition. The actuator adapter is called only after ALLOW.

## Deployment modes

### 1. Reference / all-container demo

The repository includes `runtime/docker-compose.yml` with a containerized Magic Box and a containerized host-I/O model. This is useful for deterministic development and demonstrations.

```bash
docker compose -f runtime/docker-compose.yml up --build
```

This mode does **not** demonstrate trusted hardware enforcement.

### 2. Physical host deployment

For a real device, keep the governance runtime in a container and run the physical-I/O adapter natively on the host:

```text
+--------------------------- HOST ---------------------------+
|                                                            |
|  +-------------------+       Unix socket                   |
|  | Magic Box         | --------------------------+         |
|  | container          |                           |         |
|  | GIE                |                           v         |
|  | Safety             |                 +----------------+ |
|  | Identity           |                 | host_io        | |
|  | Freshness          |                 | native process | |
|  | Commit Gate        |                 +-------+--------+ |
|  +-------------------+                         |          |
|                                                v          |
|                                         GPIO / CAN /      |
|                                         Serial / USB      |
|                                                |          |
|                                                v          |
|                                          physical device  |
+------------------------------------------------------------+
```

The Unix socket is an IPC transport, not a security boundary. The important invariant is earlier: a blocked execution never invokes the actuator adapter, so no IPC request is generated by the Magic Box for that execution.

For the first physical demo, replace the host-side `RelayHostAdapter` with a real GPIO implementation. Keep GPIO assumptions outside GIE, Commit Gate, and execution identity.

## Host I/O boundary

`runtime/host_io.py` is deliberately outside the governance core. It receives only payloads already committed by the Magic Box and translates the opaque payload at the physical-I/O edge. The current reference adapter maps `RELAY:ON` and `RELAY:OFF` to a relay model. fileciteturn338file0

For physical deployment, the same interface can be implemented using GPIO, CAN, serial, USB, TCP/UDP, MQTT or another device-specific mechanism. The governance core must not learn those protocols.

## Physical PoC acceptance criteria

The first hardware demonstration should prove:

1. **ALLOW → physical effect** — an authorized `RELAY:ON` reaches the host adapter.
2. **REVOKE → zero physical effect** — the controller continues sending commands using the old epoch, but the Magic Box blocks them before actuator IPC.
3. **SAFETY BLOCK → zero physical effect** — valid authority is insufficient when the safety decision blocks.
4. **Identity mismatch → zero physical effect** — changing the exact payload after authorization cannot produce a commit.
5. **Controller unchanged** — the autonomous controller does not need to implement GIE, Safety, or Commit Gate logic.

The central demonstration is therefore:

```text
AI continues producing actions
             |
             v
       Equinibrium Box
             |
        ALLOW / BLOCK
             |
       +-----+-----+
       |           |
     ALLOW       BLOCK
       |           |
       v           X
   actuator       no IPC
       |
       v
 physical effect
```

## PoC boundary

This container is a reference runtime, not a trusted hardware security boundary. The physical host can still compromise the software process. The purpose of this stage is to demonstrate that the same execution invariants can sit inline between an unchanged autonomous controller and a physical effect.

Production work can later map the same invariant contract into a trusted hardware execution boundary. That is intentionally outside the current Magic Box PoC scope.
